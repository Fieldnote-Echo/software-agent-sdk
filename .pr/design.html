Issue #2721 · Phase 2c

Policy rails inspect shell structure

This change replaces flattened-text regular expressions with the shared tree-sitter Bash AST. It keeps the current rail IDs and priority, and it implements issue #2721's fetch-to-downstream-command policy. It parses original shell source and returns UNKNOWN when command selection or argument positions cannot be resolved.

2. Changed code

Policy rails

Walk the Bash AST once. Inspect pipeline stages, resolved commands, device paths, and delete targets. Keep the existing rail priority.

Compare the former regular-expression path.

Shared command semantics

Resolve command names and arguments once. Preserve uncertainty when expansion can change argument count or option selection.

Compare the former scanner helpers.

Original-source parse boundary

Feed original executable segments to the parser. Keep NFKC normalization only in the separate regular-expression text path.

This prevents normalization from creating comments or shell operators before parsing.

Regression tests

Cover original Unicode source, dynamic dd operands, wrapper positions, nested producers, expansion arity, script mode across option terminators, and known controls.
